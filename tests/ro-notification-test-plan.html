2. Realtime Status Change Detection

TC-03 Realtime · Status Change Triggers Notification

Changing RO status creates a notification entry

  1. Open redlined1.com (logged in as Owner).
  2. Navigate to Repair Orders.
  3. Open any RO with status "Open" (e.g. RO-00003).
  4. Change the status dropdown to "In Progress" and click ✓ Save Changes.
  5. Watch the sidebar 🔔 Notifications button.
✅ Within 1–2 seconds: bell turns red, badge shows "1". Button border changes to red with rgba(220,38,38,0.12) background.
TC-04 Realtime · Cross-User Multi-Tab Notification

Notification appears on all connected sessions for the same shop

  1. Open redlined1.com in Tab A and Tab B (same shop, same or different user).
  2. In Tab A: change an RO status (e.g. "In Progress" → "Pending Parts").
  3. Switch to Tab B without interacting.
✅ Tab B's bell badge also shows "1" — the notification was pushed via Supabase realtime without any page action on Tab B.
TC-05 Realtime · Same-Status Save = No Notification

Saving an RO without changing status produces no notification

  1. Open any RO (e.g. status = "Open").
  2. Edit the Concern field text only.
  3. Click Save without touching the status dropdown.
  4. Watch the bell button.
✅ No new notification. Badge count unchanged. (Hook checks: if (oldRow.status === newRow.status) return)
TC-06 Realtime · Shop Isolation

Location 1 status changes do NOT appear for Location 2 users

  1. Open Tab A logged in as a Location 1 user.
  2. Open Tab B logged in as a Location 2 user (different shop_id).
  3. In Tab A: change an RO status.
  4. Inspect Tab B bell button.
✅ Tab B shows NO notification. Realtime channel is keyed by shop_id: ro-status-{sid}, preventing cross-location leakage.

8. Edge Cases

TC-25 Edge · Notification Cap at 50

System keeps only the 50 most recent notifications

  1. Simulate 51+ rapid status changes via the Supabase SQL editor:
    -- Run in Supabase SQL Editor (repeat status flip to trigger updates) UPDATE repair_orders SET status = 'In Progress' WHERE id = '<ro-id>'; UPDATE repair_orders SET status = 'Open' WHERE id = '<ro-id>';
  2. Open the notification panel and count entries.
✅ Maximum 50 entries shown. Oldest entries are dropped. (_notifications = [next, ..._notifications].slice(0, 50))
TC-26 Edge · Page Refresh Clears Notifications

Notifications are in-memory only — reset on refresh

  1. Trigger a status change (badge shows red "1").
  2. Refresh the page (F5 / Cmd+R).
  3. Inspect the bell button.
✅ Bell resets to grey with no badge. Notifications are not persisted to the database — they are session-only in the module-level JS store.
TC-27 Edge · RO Not Found in Current List

"Open RO →" gracefully handles RO not loaded in current shop view

  1. Be logged in as Location 2.
  2. Manually trigger a realtime event for an RO that belongs to Location 1 (via Supabase SQL).
  3. Click "Open RO →" for that notification.
✅ Navigates to Repair Orders module. No RO is auto-selected (find returns undefined, setSelected is not called). No console errors thrown.
TC-28 Edge · Supabase Realtime Unavailable

App remains functional if realtime channel fails to subscribe

  1. Temporarily disable realtime in Supabase project settings (Database → Replication → disable repair_orders), OR simulate offline by throttling the network to "Offline" in DevTools.
  2. Log in and use the app normally (create job cards, view ROs, etc.).
  3. Re-enable realtime afterward.
✅ App works fully. Bell renders without notifications. No unhandled errors in the browser console from the failed subscription.
