Edge Cases & Race Conditions
TC-052 – TC-055
TC-052
No redirect-to-dashboard while role permissions are loading (!permLoaded)
Race condition fixed 2026-07-17 — verify regression has not returned
edge
Pass
▼
Background: useShop() resolves faster than fetchShopSettings(). During the async window, if AppShell applied getBlockedModules('') (block-all) it would permanently redirect to dashboard. Fix: return [] while !permLoaded.
#ActionExpected Result
1Log in as technician on a slow network (throttle to Slow 3G in DevTools)During the async gap between role load and permissions load, the technician stays on their allowed module (dashboard) — not redirected to dashboard from dashboard (no loop)
2Navigate to Job Cards immediately after login before permissions finish loadingJob Cards remains visible — no redirect-to-dashboard fires during the loading window. Once permLoaded=true, the allowlist applies correctly.
Key fix (c22b8e5): While !permLoaded, roleBlocked = [] (allow all). The redirect only fires once DB permissions are confirmed.
TC-053
Billing lock screen never appears if profile DB read fails (profileLoaded = false)
Grace fallback: any DB/network error gives 14-day trial status
edge
Pass
▼
Background: usePlan.ts sets profileLoaded=false on DB error. AppShell only shows hard lock screen when profileLoaded=true AND plan='free'.
#ActionExpected Result
1Temporarily break the Supabase RLS policy (or simulate offline) and log in as technicianprofileLoaded stays false; grace trial activates; no hard lock screen appears; technician can still use the app
2Restore the RLS policy and refreshNormal plan resolution resumes; technician's plan shows correctly
Key assertion: A billing infrastructure failure must NEVER lock out users. Grace = 14-day trial on any error.
